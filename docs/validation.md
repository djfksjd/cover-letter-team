# v2 고도화 검증 기록

검증일: 2026-10-03. 비교 기준 커밋: `3379945`. 실제 지원자 자료나 실제 제출을
사용하지 않은 로컬 회귀·통합 검사와 합성 지원 건의 행동 검증이다.

## 구현 범위

한국/국제 진입 경로와 국가·법인·직무·언어·문서 라우팅, 회사 없는 경험 정리,
현재 요건/최근 연도 비교/조건부 사례 조사 정책, EXP/RSH/FIT와 필수 하위요소의
근거 대응, 부족한 정보 질문과 중단 조건, 문체/문항/직무별 참고 지침을 반영했다.
34개 공개 출처의 적용 범위를 references에 유지하고 공식 조건·일반 권장·운영 판단을
구분했다. 모든 기업의 과거 공고나 공개되지 않은 내부 기준을 확보한 것은 아니다.

기계 구현은 strict YAML, 중복/잘못된 ID·승인값 차단, 카드 내용 해시, 정확한 claim
텍스트/필드/값 대조, 새 숫자 토큰 검사, 필수 요건 매핑, 문항·공식 분량,
최신 입력의 리뷰·최종 승인 결합, 미승인 파일 미리보기와 검토된 DOCX의 동일 바이트
산출이다. 의미와 사람의 실제 동의는 리뷰/대화의 책임이며 해시가 그 진실을 증명하지 않는다.

## 회귀·통합 검사

깨끗한 임시 가상환경에서 requirements-dev.txt로 설치해 확인했다.

```text
python -m pytest -q                         110 passed
python -m ruff check scripts tests          All checks passed!
python -m ruff format --check scripts tests  20 files already formatted
skill-creator/scripts/quick_validate.py .   Skill is valid!
pip-audit -r requirements.txt               No known vulnerabilities found
```

로컬 Python은 3.14이며 CI는 3.11/3.14에서 같은 검사를 실행한다. CI 액션은 검증된
공식 커밋 SHA에 고정하고 의존성/하위 의존성 버전을 고정했다. 감사 결과는 검사 시점의
알려진 취약점 조회 결과이며 모든 보안 문제의 부재를 증명하는 것은 아니다.

중요한 경계 검사는 YAML 주석/중복 키/ID/문자열 boolean, NONE/중복 DERIVED,
잘못된 마커·주석 없는 후미·추가/중복/누락 문항·가짜 Q preamble, 새 숫자 성과,
필드값/승인 해시 불일치, 필수 갭의 모든 상태, AI 작성 금지, 지원 건 오염,
누락/오래된 claim/요건 리뷰·최종 승인, 경로 이탈, 파일 미리보기 변경,
Unicode/UTF-8/UTF-16/CRLF/501개 줄바꿈 영어 단어와 실제 렌더링된 본문 분량이다.

같은 숫자가 근거에 있다는 사실만으로 다른 단위/성과를 쓴 문장의 의미를 보증하지
못하는 한계도 테스트에 명시했다. 이런 문장은 의미 리뷰 실패 시 산출이 차단된다.

## 독립 요청 검토와 수정

구현 과정과 별도 컨텍스트의 에이전트가 다음 요청을 적용했다.

1. 회사·숫자 없이 경험 정리: 기업 입력과 제출 검사 없이 EXPERIENCE_ORGANIZED 종료.
2. 한국 기업 런던 법인 영어 supporting statement: 국적/문서 분리, essential criteria
   원문 우선, 과거 자료 not_comparable, 편지 인사말 강제 없음.
3. 3회 수정 후 개인/팀 역할 불명: HIGH 유지, DRAFT_WITH_ISSUES, 제출 export 금지.

첫 검토에서 비제출 모드의 종료 분기와 파일 레이아웃 확인의 순환 의존을 발견했다.
명시적인 비제출 종료 경로와 미승인 workspace 미리보기 단계를 추가한 뒤 재검토했다.
후속 검토에서 두 결함이 해결됐으며 신규 차단급 충돌을 찾지 못했다.

## 실제 합성 작성 시나리오

영문과 한국어 지원 건은 각각 별도 평가 에이전트가 제공된 가상 원자료만으로 실제
v2 파일을 작성하고 스크립트/리뷰/합성 승인/산출까지 실행했다. 각 평가 에이전트 내부의
작성과 내용 재검토는 같은 컨텍스트였다. 별도 독립 Reviewer 검증으로 포장하지 않았다.

| 지원 건 | 최종 본문 | 확인한 품질 |
|---|---|---|
| 영어 supporting statement, 최대 500 words | 32 words | 본인 체크리스트 작성과 팀 사용, 효율 수치/주도권 창작 없음, 편지 인사말 없음 |
| 한국어 협업 갈등, 최대 600자 | 403자 | 갈등 쟁점·인터뷰 8건 중 본인 5건·표 공유·수정 제안·팀 합의/개발 팀원 수정·팀 결과/사후교훈 분리 |

필수 내용 범위의 PASS를 확인했다. 영문 원자료가 짧으므로 해당 결과로 경쟁력 전반이나
합격 가능성을 평가할 수는 없다. 필요한 내용을 충족하는 짧은 글을 일반론으로 늘리지
않는 행동을 확인했다. 한국어 글도 90% 분량이나 회사동기·문체 샘플을 추가 강제하지 않았다.

영어 줄바꿈 제거가 단어를 병합하는 결함은 실제 작성 테스트에서 발견해 수정했다.
한국어 DOCX가 문단 내부 줄바꿈을 공백으로 바꾸는 차이를 발견한 뒤 실제 제출 렌더링
기준으로 검사·MD/DOCX를 통일했다. 초기 397자 대신 최신 본문 403자로 검증한다.
이 변경에는 검사 revision을 해시에 포함해 이전 리뷰·승인이 자동으로 무효화된다.

## 남는 한계와 운영 확인

- 실제 채용 담당자 평가·합격률·질문 부담의 대규모 실험은 수행하지 않았다.
- 의미 적합성·인과·역할·근사 정밀도·실제 사용자 확인은 근거를 읽는 에이전트/사람의 책임이다.
- portal 카운터, 실제 페이지/업로드, 고용주 AI/blind 정책은 개별 지원에서 확인한다.
- DOCX 텍스트/제목 roundtrip은 시각 레이아웃 검증과 다르다. 명시 파일 조건에는 preview+file review를 사용한다.
- 영어 외 언어의 현지 관례·공식 작성 안내는 추가 확인하며 미국식 편지를 자동 적용하지 않는다.
- 지원 사이트 제출·이메일 발송은 수행하지 않는다. 공개 Git에는 지원자 파일/합성 승인 작업 폴더를 넣지 않는다.


## 후속 엄격 심사 (내용 완성도 보완)

별도 심사 에이전트가 기존 review/보고서/작성자의 설명 없이 문항과 본문을 먼저 읽고,
그 뒤 카드와 대조했다. 기존 한국어 403자는 ADEQUATE, 영어 32단어는 THIN으로 평가했다.
영어는 사실·형식이 정확해도 실제 문제·체크리스트 내용·선택 근거가 없어 수행 능력을
평가할 정보가 부족했다. 한국어는 기본 답변은 완성됐으나 합의 과정의 디테일이 개선 여지다.
따라서 이전 PASS를 최고 품질이나 풍부함 PASS로 해석해서는 안 된다.

content_reviews를 필수 계약으로 추가했다. 모든 문항의 STRONG/ADEQUATE/THIN/NOT_READY,
실제 claim 근거, assessment, blocking_gaps, improvement_opportunities를 기록한다.
THIN/NOT_READY 또는 열린 차단 갭은 기존 factual/format PASS와 무관하게 export를 막는다.
실제 기존 32단어 사례에 독립 THIN 판단을 적용해 DRAFT_WITH_ISSUES와 산출 차단을 확인했다.
검사 revision 2.2는 이전 리뷰·승인을 무효화한다. 회귀 검사는 110개 통과했다.

새 별도 합성 사례에는 원래 사용자에게서 얻지 않은 사실을 이전 경험으로 추가한 것이
아니라, 처음부터 더 풍부한 가상 원자료를 제공했다. 인수인계 문제, 실제 네 개 항목,
중복 항목 제외 이유, 피드백 수정, 팀장의 도입 결정, 세 차례 직접 사용/원본 대조를
156단어로 작성했다. 작성자의 자체 평가는 STRONG이었으나 별도 문항/본문 우선 심사에서는
ADEQUATE였다. 최종 기록은 더 보수적인 ADEQUATE를 채택했고 근거 있는 디테일과 좁은
결과 범위, 반복/마무리의 개선 여지를 공개했다. 실제 최종 사용자 승인/export/제출은 없다.

이 검증은 충분한 사실로 정보량을 높일 수 있으며 빈약한 글은 보충 확인으로 돌려야 함을
확인한다. 모든 결과가 최고 품질임을 보증하거나 더 높은 등급을 얻으려고 사실·숫자를
추가해서는 안 된다. 최신 정책은 references/content-quality.md를 따른다.
