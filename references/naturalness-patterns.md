## 무엇을 가져왔고 왜

| 가져온 것 | 이 스킬에서 쓰는 방식 |
|---|---|
| **심각도 S1/S2/S3** | 후보 출력에 붙여 읽는 순서를 정한다. HIGH 판정은 아니다 |
| **문서·문단 밀도 임계** | 한 번 나온 표현은 대부분 정상이다. 반복될 때만 후보로 낸다(D-01 4회, C-11 3회, J-02 5회 등) |
| **사람이 더 쓰는 표현의 기본 보존** | "~에 대해"(A-01)·"~를 통해"(A-02)·"~을 위해"(A-11)는 im-not-ai 실측에서 사람이 2~3배 더 썼다. 한 문단에 3회 이상 몰릴 때만 낸다 |
| **서법 보존** | "~할 수 있다" 반복(A-10)·완곡(G-02)은 단정으로 바꾸지 않는다. 주장 강도를 바꾸는 것은 claim 변경이다 |
| **주입 금지** | 고친 글에 원래 없던 패턴이 새로 생기면 안 된다. `surface_check.py --compare OLD NEW`가 확인한다 |
| **수치 보존** | `--compare`가 사라진 숫자·새 숫자를 따로 보여 준다. 새 숫자는 승인된 카드에 있는 값이어야 한다 |
| **연결어미 뒤 쉼표(C-11)** | KatFish 연구 기반 신호. 개별 쉼표는 정상이라 3회+ 후보, 6회+ S1 |

## 자기소개서에 맞춰 뺀 것

- **E-2 동일 종결어미 연속**: 합쇼체 자소서는 거의 모든 문장이 "~습니다"로 끝난다. 정상이므로 쓰지 않는다.
- **E-1 문장 길이 균일**: 리듬을 목표로 삼지 않는다(SKILL.md 3단계). 평균·표준편차만 참고로 출력한다.
- **A-16 대명사 문맥 판정**: 자동 판정이 불확실하고, im-not-ai도 빠른 경로에서 뺐다. Reviewer가 읽을 때 본다.
- **변경률 30%/50% 게이트**: 이 스킬은 윤문기가 아니라 근거 기반 작성이다. 대신 claim-map이 사실을 지킨다.
- **Layer B·탐지기 점수 최적화**: 이 스킬의 목표(AI 탐지 회피 아님)와 맞지 않는다.
- "기여하겠습니다"류는 상투 마무리로 잡지 않는다. 구체적인 일과 함께 쓰면 정상 마무리다.

## 후보를 다루는 법

1. 후보는 "이 문장을 다시 읽어 보라"는 표시다. 문맥에 맞으면 그대로 둔다.
2. 고칠 때는 사실·수치·역할·주장 강도를 바꾸지 않는다. 바꿔야 하면 Writer가 아니라 Director 확인 사항이다.
3. 고친 뒤 `--compare`로 새 패턴·숫자 변화를 확인한다.
4. 후보 개수로 HIGH를 주지 않는다. 읽는 사람이 실제 행동을 못 보게 가리는 경우만 MID 이상으로 적는다.
