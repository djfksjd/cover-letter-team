# 입력·정보 충분성·질문 정책

## 입력 모드

experience_inventory는 지원 대상 없이 실제 경험을 구조화한다. general_draft는 범용
검토용이며 맞춤 제출 가능이라고 표시하지 않는다. targeted_application에는 현행
공고/사용자 원문의 회사·법인·직무·문항·형식이 필요하다. URL·파일에서 알 수 있는
항목은 다시 묻지 않고 비어 있는 값만 묻는다.

회사 국적과 채용 국가, 작성 언어, 문서 유형은 독립 값이다. 외국계 한국 지사 한국어
문항과 한국 회사 해외 법인 영문 cover letter를 구분한다. 국가는 단순 관례보다 해당
공고의 구체 요건을 먼저 적용한다. 지역 관례 미확인은 기록하되 임의의 규칙을 만들지 않는다.

## 세 종류의 판단

1. 결정적 검사: 필수 입력·ID·승인/해시·문항·공식 분량·해결되지 않은 요건 매핑.
2. 근거 기반 판단: 실제 행동·회사 선택 이유·역할·직무 연결의 충분성. 위치·필드·
   판단 이유를 제시하며 완전히 객관적이거나 합격 확률이라고 설명하지 않는다.
3. 선택 개선: 소제목·리듬·어휘 선호·추가 장면. 필수 요구가 아니면 그 자체로 차단하지 않는다.

## 충분성

행동 문항에는 개인 행동/판단과 실제 결과가 필요하다. 결과는 숫자 외 산출물·변화·
피드백도 가능하다. 실패 문항에는 실제 실패·책임·수정 행동이 필요하며 성공 성과를
강제하지 않는다. 지원동기에는 사용자가 말한 선택 이유가 필요하고 RSH 소개만으로
대신하지 않는다. 계획에는 본인이 하고 싶은 일·현실적 역할 이해가 필요하다. 회사
동기가 없는 문항에는 FIT/독점 회사 사실을 강제하지 않는다.

## 갭 상태와 처리

| 상태 | 의미 | 처리 |
|---|---|---|
| UNKNOWN | 아직 확인되지 않음 | 기존 자료 확인 후 필요한 질문 |
| MISSING | 필수 정보/매핑 부재 | 담당에게 확보 요청 |
| CONTRADICTORY | 기간/역할/수치/요건 모순 | 해결 전 주장 확정 금지 |
| WEAKLY_SUPPORTED | 주장보다 약한 근거 | 범위 축소·대체 근거·보충 확인 |
| NOT_APPLICABLE | 선택 항목이 이번 문항에 불필요 | 추가 질문 없음; 필수 항목에 사용 불가 |
| NO_ACTUAL_EXPERIENCE | 사용자가 없다고 확인 | 반복 질문 금지; 대체 소재/한계 설명 |
| SUFFICIENT | 근거 필드로 요구를 충족한다고 판단 | 이유 기록 후 본문에서 Reviewer 재검토 |

먼저 파일·인터뷰·공개 정보를 확인한다. 회사 사실은 Researcher, 개인 행동·의사는
사용자, 스키마 오류는 도구 담당이 해결한다. 질문은 한 번에 1~2개이며 목적과 해결
조건을 설명한다. ‘제안/실행 중 어느 단계까지 맡았나요?’, ‘결과를 어떤 자료나 반응으로
확인했나요?’처럼 열린 질문을 쓴다. ‘20%로 쓰면 되죠?’ 같은 유도 질문은 하지 않는다.
모른다는 답 뒤에 같은 질문을 바꿔 반복하지 않는다. NDA·개인정보는 말하지 않아도 된다.

## 재검토와 종료

공고 변경은 requirements와 관련 계획/본문/검사를 갱신한다. 카드의 사실 내용 변경은
그 카드의 승인을 무효화한다. 문체 수정도 의미가 달라졌으면 재대조한다. unchanged
경험을 재인터뷰하지 않는다. input_hash가 달라지면 기존 review/final approval는 무효다.

INTAKE → REQUIREMENTS_READY → EVIDENCE_READY → DRAFT → REVIEW → READY_FOR_USER_REVIEW
→ APPROVED_FOR_EXPORT → EXPORTED. 정보 부족은 NEEDS_USER_INPUT, 상한에서 문제가
남으면 DRAFT_WITH_ISSUES. 코드의 DRAFT_VALIDATED는 REVIEW 전 형식 검증 상태다.
3회 자동 리뷰 상한은 제출 PASS를 허용하는 예외가 아니다.

최종 확인은 본문 전체·해석·지원 이유/포부·변경된 사실을 대상으로 하고 확인 전에
최종 파일을 만들지 않는다. 파일 생성은 지원 사이트 제출과 다르다. DOCX 텍스트 검사
외에 실제 표시·페이지 수·첨부 요건은 시각/포털 확인으로 검토한다.


비제출 모드: experience_inventory는 EXPERIENCE_ORGANIZED, general_draft는
DRAFT_FOR_CUSTOMIZATION으로 끝낸다. 해당 모드에는 현재 공고/문항 매핑과 제출 validator를
실행하지 않는다. 공식 파일 조건 검토가 필요하면 승인 전 workspace/preview에 미승인 검토
파일을 생성한다. 이는 output 최종 파일이 아니며 실제 페이지/형식을 검토한 뒤 승인한다.
